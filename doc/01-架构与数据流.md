# 01｜架构与数据流

## 分层

```
┌─────────────── IM 侧（平台协议） ───────────────┐
│ 微信 iLink 长轮询        QQ OneBot 反向HTTP       │
└──────┬──────────────────────────┬──────────────┘
       │ 归一化 Message             │ 归一化 Message
       ▼                            ▼
┌──────────────── Channel Manager (manager.py) ────────────────┐
│  on_message(msg): 路由                                          │
│    "/new"           → _cmd_new（杀会话）                        │
│    空消息             → 忽略                                    │
│    其他               → _deliver（线程）                        │
│  _get_session(cid): 取/建常驻 Agent 会话                        │
│  _compose_input():   附件落盘 + 任务文本拼装（单物理行）          │
│  TaskSocket:         Agent 回话 socket 服务(JSONLines)          │
│  _verify_path/_clean_reply/_collect_attachments                 │
└──────┬──────────────────────────────────────┬─────────────────┘
       │ spawn stdin 写单行                    │ channel-reply / channel-send-file
       ▼                                        ▼
┌─────────────── Agent（本地子进程，任意实现） ───────────────┐
│ 读 stdin → 处理 → 调 channel-reply/send-file（或裸 socket） │
└──────────────────────────────────────────────────────────────┘
```

## 统一消息模型（Message）

所有平台消息进入 manager 前必须归一化成如下 dict（字段不全会出问题）：

```python
{
  "platform":       "qq" | "wechat" | "local",
  "conversation_id":"private:<uid>" | "group:<gid>",   # 会话身份，进 Agent 上下文隔离键
  "sender_id":      "<uid>",                            # 回复目标
  "account_id":     "<微信bot账号id>",                  # 微信多账号时指定回话 bot；QQ 可空
  "message_id":     "<平台消息id>",                     # 幂等/日志用
  "text":           "去掉@/平台噪音后的纯文本",
  "attachments":    ["http(s)://...", "/本地/路径"],     # 尽量给 URL；管理器负责落盘
}
```

`conversation_id` 命名规范（跨平台不撞）：
- QQ 私聊 `private:<qq>`；QQ 群 `group:<gid>`（群仅 @bot 触发）
- 微信私聊 `private:<wxid>`

## 会话并发模型（触发式常驻）

- 一个 `conversation_id` = 一个常驻 Agent 子进程 = 一份独立上下文。
- 同会话多条消息：stdin 排队串行喂给同一进程 → 上下文自然延续。
- 跨会话：各自进程、各自 runtime 目录 → 天然并行，0 串台。
- 只有 `/new` 显式重置（杀旧进程；下条消息 spawn 全新的）。
- 无主动过期；manager 退出时 `_kill_all_tasks` 清杀全部子进程（防孤儿）。

会话 dict 关键字段（manager._spawn_session 构造）：

| 字段 | 含义 |
|---|---|
| cid / sid | 会话键 / 会话 uuid(hex12) |
| rt | runtime 目录 `runtime_dir/runtime/sess_<sid>/` |
| inbox | `rt/inbox/` 附件按轮次 `inbox/<seq>/` 落盘 |
| socket_path | `rt/api.sock`（TaskSocket，0600） |
| log_path | `rt/agent.out`（Agent stdout 全文，仅日志不外发） |
| proc / process | subprocess.Popen 句柄 |
| wlock | stdin 写锁（多线程串行投喂） |
| seq | 轮次计数（附件目录用） |
| dying | 优雅终止标记 |

## 消息生命周期（一条 QQ 私聊消息为例）

1. NapCat 反向 HTTP POST 事件 → qq.py `_Handler.do_POST`，**先回 200**（防重试堆积），再起线程处理。
2. `QQAdapter._on_event`：`post_type=="message"`，`message_type=="private"` → 归一 Message，
   `receive()` → `manager.on_message()`。
3. `on_message` 起线程 `_deliver`；`_get_session` 无会话则 `_spawn_session`：
   - 建 `rt/` + TaskSocket(0600) + env(`CHANNEL_TASK_ID`/`CHANNEL_SOCKET`)
   - `Popen([sys.executable, agent_path], stdin/stdout=PIPE, start_new_session=True, cwd=agent所在目录)`
   - `_drain` 线程持续读 stdout 写 `agent.out`（尾 80 行留用于诊断）
4. `_compose_input`：附件 URL/路径落盘 `inbox/<seq>/`，拼 `[图片] ... [附件] ... 正文`，
   末尾附加 `get_agent_note()` 协议强化语；`sanitize_text` 压成**单物理行**后写 stdin。
5. Agent 完成任务 → `channel-reply "..."` → TaskSocket `_dispatch` → 应答 `{"ok":true}`。
6. manager `reply()`：`_clean_reply`（去 "你> " 提示符残影、字面 \n）→ `Adapter.send_text` → QQ 发回聊天。
7. 文件回传 `channel-send-file "<路径>"` → `_verify_path` 白名单校验 → `Adapter.send_file`。

## Socket 回话协议（Agent → Manager）

- 传输：Unix Socket，路径在 env `CHANNEL_SOCKET`；权限 0600；只监听回环内本进程。
- 帧格式：**JSON Lines，一次一帧**（以 `\n` 结尾的一行 JSON）。
- 请求帧：

```json
{"type": "reply", "text": "回复内容"}
{"type": "file",  "path": "/绝对/路径"}
```

- 应答帧：`{"ok": true}` 或 `{"ok": false, "error": "..."}`。
- 设计取舍：不用 HTTP/WebSocket，Unix Socket + JSONLines 最轻、天然按 task_id 隔离。

## 附件语义

- 入方向：IM 图片/文件尽量以 **URL** 进 attachments；`_collect_attachments` 下载到
  `inbox/<seq>/` 并返回本地绝对路径列表。
- 任务文本标注（由 config `multimodal` 控制）：
  - ON（默认）：图片扩展名(`.jpg/.jpeg/.png/.gif/.webp`) → `[图片] 路径...`；其他 → `[附件] 路径...`
  - OFF：一律 `[附件] 路径...`（给不支持图片的 Agent 用）
- 出方向：`channel-send-file` 只允许 `allowed_file_dirs` 内的文件（见 05 配置）。
- 微信现状：入方向图片/文件**不自动下载**（无 key 解密），仅文本摘要提示；出方向文件发送
  （CDN+AES）未实现，Agent 请用文字+链接代替。

## 出口职责分离

| 出口 | 用途 |
|---|---|
| Agent stdout | 只落 `agent.out` 会话日志，绝不当回复外发 |
| `channel-reply` | 主动把文本发回当前聊天（唯一文本出口） |
| `channel-send-file` | 发文件 |
| 回传错误 | Agent 崩溃/超时 → manager 自动回 `[Channel 错误] ...`，提示用户 `/new` |
