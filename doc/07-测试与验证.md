# 07｜测试与验证（无真实 IM 也能验）

## 1. 纯协议链路（最快）

```bash
python3 channel/manager.py --test "你好"
# → 尾部打印 outbox-local.log，出现 demo-agent 回复即链路通
# 换真 Agent 后再跑同一条命令 = 全链路验收
```

`--test` 行为：注入 1 条 local 消息 → 等 `agent.out` 连续 3s 无增长判完成 → 杀任务 →
打印回复日志。超时上限 min(task_timeout, 180s)。

## 2. 常驻 + 多次会话

```bash
python3 channel/manager.py --serve     # 终端A
python3 channel/manager.py --test "第一条"   # 终端B：开一个会话
python3 channel/manager.py --test "第二条"   # 再跑：注意 --test 是独立进程注入
```
验证 `/new`：给常驻会话发 `/new`，观察旧进程被杀、下条消息全新 spawn。

## 3. QQ 全链路（不装 NapCat，用桩 OneBot 服务器）

1. 配 `channel/config.json`：`adapters:["qq"]`，qq 段填 bot_qq 假号、
   `onebot_http` 指向桩地址、webhook_local 用默认 18086。
2. 起一个假 OneBot 服务器脚本：收 `/send_private_msg` 打印 body → 回 `{"status":"ok"}`。
3. `python3 channel/manager.py --serve`，向 `127.0.0.1:18086/onebot` POST 一条
   OneBot 私聊事件（type=message, message_type=private, message=[{type:text,...}]）。
4. 断言：桩服务器收到带 demo-agent 回复的 send_private_msg body。

**群 @ 双形态验证**：分别用 segment 形式与 CQ 字符串形式的 at 段 POST group 事件，
确认都触发、且传给 Agent 的正文已去 @；未 @ 的 group 事件必须不触发。

## 4. 微信链路

无真实登录态时无法全链路；已验证边界：
- 归一化逻辑单测通过（账号路由/消息过滤/context_token 记忆）。
- 真实验证路径：控制中心「微信登录」扫码 → 手机上发消息 → 观察 agent.out 与聊天回话。

## 验收清单（改完核心后至少跑 1）

- [ ] `--test` 正常回复（local 适配器）
- [ ] 附件 URL 能落盘 inbox 并在任务文本出现 `[图片]/[附件]` 标注
- [ ] `/new` 重置会话
- [ ] Agent 崩溃（故意 exit 1）→ 聊天收到 `[Channel 错误]` 且进程被清理

- [ ] QQ 私聊/群@/未@忽略 三态正确
