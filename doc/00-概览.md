# 00｜概览（面向 Agent 的项目文档）

> 本目录所有文档是给 **Agent/自动化开发者** 读的，不是给终端用户读的。
> 阅读顺序：00 概览 → 01 架构与数据流 → 02 会话与运行时 → 03 Agent接入协议 → 04 适配器开发
> → 05 配置参考 → 06 控制中心与部署 → 07 测试与验证 → 08 已知坑与边界。

## 项目是什么

一个「IM 外部通道」：把 **微信 / QQ** 的消息转成任务喂给 **任意 Agent**（本地子进程），
再把 Agent 的回复 / 文件发回原聊天。Agent 不需要知道 IM 的任何协议。

- 微信：自研 iLink 客户端（逆向官方 openclaw-weixin 公开协议），getUpdates 长轮询收 / sendmessage 发。
- QQ：OneBot11（NapCat / Lagrange），反向 HTTP 收事件，HTTP POST 正向 API 发。
- Agent：本地子进程，stdin 收单行任务，Unix Socket 主动回话。

## 设计铁律（改动前必须读）

1. **零第三方依赖**：全部 Python 标准库。不引入 requests/flask/aiohttp。
2. **不改 Agent 本体**：Agent（如 term_agent.py）一行都不用改；所有适配在通道层完成。
3. **stdout 不是外发通道**：Agent 的 stdout 只落会话日志 `agent.out`；唯一外发出口 =
   Agent 主动调 `channel-reply` / `channel-send-file`。
4. **不加常驻后台设施**：不加数据库/Redis/daemon/systemd/全局队列；manager 常驻由
   control.py 用 PID 文件管理。
5. **触发式**：只有收到 user 消息才动（往 Agent stdin 写一行）；其余时间主线程纯静态阻塞。
6. **平台无关消息模型**：适配器必须把平台消息归一成统一 Message dict（见 01 节）再交上层。
7. **Agent 附着方式 = 可替换边界**：默认为「spawn 本地子进程」；想接其他形态（如某端口上
   的远程 Agent）就替换 `ChannelManager._spawn_session` 里的驱动或写转发壳（见 03 节）。

## 常用入口速查

| 想做 | 入口 |
|---|---|
| 全链路自检（无真 IM） | `python3 channel/manager.py --test "你好"`，看 outbox-local.log |
| 常驻启动 | `python3 channel/manager.py --serve` |
| 加一个 IM 平台 | 见 04 适配器开发（改 adapters/ + 工厂注册，不碰核心） |
| 接入一个自己的 Agent | 见 03 Agent接入协议 |
| 改配置 | 见 05 配置参考（channel/config.json，0600） |
| 跑桌面控制中心 | `python3 control/control.py` 或 `./install_desktop.sh` |
