# 08｜已知坑与边界（改代码前先看）

## 输入侧

1. **Agent `input()` 一次只读一行** → 多行任务必须压成单物理行（`sanitize_text` 折叠换行）。
   给 Agent 的 stdin 永远一行；不要在投喂端制造多行。
2. **Agent 有 key.bin 等已初始化文件时**跳过交互 welcome()——否则首行任务会被当 API Key 读走。
   这是 term_agent.py 类 Agent 的事，通道不负责，但排查"任务没执行"时先想到它。
3. **QQ 反向事件 body 可能没有 Content-Length**（NapCat 真实 chunked）。HTTP handler 必须
   兼容 CL + chunked 两种读法，否则事件被静默丢弃（表现为"QQ 收不到消息"）。
4. **QQ 群 @ 识别要双形态兜底**：segment 形式 `{"type":"at","data":{"qq":...}}` 与
   CQ 字符串形式（NapCat 不同配置上报形态不同）。

## 回话侧

5. **Agent 回话文本可能带 `你> ` 提示符残影 / 字面 `\n`**：`_clean_reply` 统一清洗；
   新 Agent 若自带终端提示符，记得在通道层或 Agent 层处理，别让残影进聊天。
6. **唯一出口纪律**：Agent 只要调过 `channel-reply` 就算已回复；stdout 永不外发。
   改动时别引入"stdout 兜底外发"逻辑（会与主动回复打架造成双发）。
7. **文件发送白名单**：`allowed_file_dirs` 是整体替换语义；Agent 想发别的目录需显式加白，
   不能靠默认值继承（配置里一旦写就覆盖默认）。

## 生命周期/并发

8. **子进程必须能自然退出**（EOF/exit），`_drain` 才收尾清理；僵尸会话会占 runtime 目录。
   退出时 `_kill_all_tasks` 用 killpg 清杀整个进程组（防 Agent 再拉起孙进程成孤儿）。
9. **清理用 python `shutil.rmtree`/`os.remove`**——项目纪律（shell `rm` 易踩危险命令黑名单/误删）。
10. **端口 TIME_WAIT 残留**：QQ HTTP 服务要 `allow_reuse_address=True`，否则 manager 重启时
    端口占用会连带把微信通道一起拖垮（单适配器启动失败只跳过该适配器，但也别制造这种失败）。
11. **写临时配置文件先验证存在再跑**：`CHANNEL_CONFIG`/config.json 指向不存在文件时
    load_config 静默回落默认 agent（曾因此意外跑错 Agent）。

## 平台边界（诚实说明）

12. **微信媒体文件**：入方向图片/文件不自动下载（逆向通道无官方 key 解密），只给文本摘要；
    出方向文件发送（CDN+AES）未实现——微信场景让 Agent 用文字+链接。
13. **微信/QQ 账号风险**：iLink 为逆向公开协议、QQ 走 NapCat 第三方实现，均有平台风控可能；
    项目按"个人自用/学习"定位，不承诺可用性。
14. **context_token 记忆**：微信官方按"userId 最新 context_token"语义记忆；每条新消息覆盖，
    实现已对齐，别改成累加（官方不是这么记的）。
15. **`--test` 超时上限 = min(task_timeout, 180)s**：超长任务用 `--serve` 真实验证，别用 --test 判死刑。
16. **多模态 OFF 不是去掉附件**：只是把图片从 `[图片]` 标成 `[附件]`（给无视觉 Agent 的开关）。
