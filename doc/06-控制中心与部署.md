# 06｜控制中心与部署

## 桌面入口

- 启动器模板 `control/Agent-Channel.desktop` 用占位符（`__PY__`/`__CONTROL_PY__`），
  不能直接双击；跑仓库根 `./install_desktop.sh` 生成实际入口
  （安装到 `$XDG_DATA_HOME/applications`，按脚本自身位置定位项目，可重复执行）。
- 桌面放快捷方式：`cp ~/.local/share/applications/Agent-Channel.desktop ~/Desktop/ && chmod +x`。
- 依赖说明：control/qqdeploy 二维码渲染可选 segno，无则退化为 URL 提示。

## control.py（TUI 主面板）

```bash
python3 control/control.py
```
菜单：
| 键 | 功能 |
|---|---|
| 1 | 启动/停止 Channel（PID 文件防重复启动；stop 清杀全部 Agent 子进程） |
| 2 | 微信登录（未登录拉 QR；已登录可 r 重登） |
| 3 | QQ 登录（自动部署/拉起 NapCat + QR） |
| 4 | 多模态 ON/OFF（持久化到 channel/config.json） |
| 5 | 刷新状态（Channel 运行态 + QQ/微信登录态 + 多模态） |
| 0 | 退出 |

- 面板状态：Channel `●运行中/○未运行/!异常(残留PID)`；QQ/微信 `●已登录 / ○未登录`；
  多模态 `●ON / ○OFF`。
- control 只做控制层，**不碰 Agent 核心与 Channel 消息逻辑**；通过 `channel/config.json`
  复用同一份配置；让 control 可直接 import `channel/ilink`（微信登录）。

## QQ 部署（qqdeploy.py）

- 目标：本机跑起 **NapCat**(QQ NT 协议) + 配置 OneBot：
  - NapCat 监听：WebUI / API（发消息）在本机端口；HTTP 客户端 → `127.0.0.1:18086/onebot`
    反向推送事件给 qq 适配器。
  - 二维码：从 NapCat WebUI/数据目录取最新二维码 URL → 终端渲染/提示扫码 → 轮询登录结果。
- 安装根目录：`~/.local/share/agent-terminal/qq/`（AppImage runtime 形态）。
- 状态检测维度：installed / logged_in / running / webui / api（多维判断，异常可提示修复）。

## 目录与日志

| 项 | 位置 |
|---|---|
| Channel PID / 状态 | `/tmp/agent-channel/channel.pid` / `channel.state.json` |
| manager 日志 | `/tmp/agent-channel/channel.log` |
| local 回复 | `/tmp/agent-channel/outbox-local.log` |
| 会话 stdout | `/tmp/agent-channel/runtime/sess_<sid>/agent.out` |
| 微信登录态 | `~/.local/share/agent-terminal/channel/ilink-weixin/accounts/` |
| NapCat 数据 | `~/.local/share/agent-terminal/qq/` |

## 多账号 / 多通道并行

- 微信支持多账号：登录多个后 wechat 段 `accounts` 列表选启用；消息带 account_id 路由回对应 bot。
- 一个 manager 可同时启用 `local + qq + wechat`；单个适配器启动失败只跳过，其余通道照常。
